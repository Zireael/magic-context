# v0.45.1 (draft)

## Fixes

- **`cache_ttl` edits apply to existing sessions** (issue 624, reported by @null-axiom). User and project TTL settings take effect on the next pass in OpenCode, Pi and the Rust module; only built-in defaults remain frozen per session. `/ctx-status` now distinguishes your config from the frozen built-in default. Raising the TTL keeps the warm prefix intact; lowering it only rebuilds after normal idle expiry.
- **Smart notes wait out GitHub rate limits instead of parking public repositories.** Compile dry-runs and scheduled checks now recognize secondary-limit response bodies as well as reset/Retry-After headers, retry without failure strikes, and acknowledge unavailable-check warnings after delivery so they do not repeat on later turns (OpenCode and Pi).

- **OpenCode 2: per-model execute thresholds now apply** (#622, reported by @Tahmid-kabir-addin). Per-model entries in `execute_threshold_percentage` and `execute_threshold_tokens` were ignored on OpenCode 2, so every session used `default` for when queued drops run and when the historian starts. OpenCode 1 and Pi were not affected.
- **Shorter database lock holds after a history summary.** Choosing which drops to queue after the historian publishes now happens before taking the write lock, so other sessions' turns no longer wait behind it (OpenCode and Pi).
- **Faster, bounded compaction-marker writes on OpenCode.** The lookup before writing the compaction boundary into OpenCode's database now uses the per-message index (1.7 s to under 1 ms on a million-part session), and the write waits at most 250 ms for OpenCode's own writer before retrying on the next rebuild. Marker removals keep their longer wait.
- If the model asks `ctx_reduce` to drop the tag for that same `ctx_reduce` call, skip that tag and briefly explain why in the tool result; drop any other requested tags. (issue 623)
- **Rust module, model runner:** historian and dreamer sends to a configured module runner carry a per-attempt `send_id`, so a resend after a lost reply doesn't start a second run; route-open refusals use the runner's typed class.
- **Smart-note checks no longer time out on slow sites.** A check could be stopped after 2 seconds while its web request was allowed 5, so a slow GitHub answer failed the check and, after three such failures, downgraded a healthy note. Checks now get the full request time, and a network timeout is retried later without counting as a failure.
- **Fallback resends are judged on the provider's measured size.** When Magic Context resends the last good request because the current pass failed, it now uses the provider's measured size of that request plus an estimate for the new messages, instead of re-estimating the whole request. A large session could otherwise be refused at an estimate well above its real size.
- **OpenCode 1 Rust mode moves the compaction marker past partial summaries again.** The marker had stopped advancing, so OpenCode sent nearly the whole conversation every turn (thousands of messages on long sessions), slowing every pass.
- **(HELD: reverted on master pending end-to-end fixes) `protected_tools`: keep the newest results of chosen tools (#621).** A new map from tool name to a count, for example `"protected_tools": { "ask_user": 3 }`, keeps the newest N completed results of each named tool out of every automatic drop, at any context pressure. A `ctx_reduce` request on a protected result waits until newer calls push it out of the protected count. `todowrite: 1` and `ctx_reduce: 3` are the defaults. The `smart_drops` setting is retired: superseded edits and spent control outputs are always cleaned up on passes that already rebuild the cache, and an old `smart_drops` key still loads with a warning in `doctor`. If protected results alone can't fit the model's window, the turn is refused with an explanation instead of being sent over the limit.
